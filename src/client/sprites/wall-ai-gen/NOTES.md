# Wall level artwork — AI-generated (2026-11-08 replacement)

These five images replace the procedural Canvas wall art in `wall-render.ts`
(which is now disabled — see that file's own header) and the earlier LPC-crop
tile fill in `sprites/lpc/fortress/wall-level-*.png` (still present on disk,
no longer referenced by any level).

## Provenance

Generated by the user via OpenAI ChatGPT's image generation tool, at the
user's own request, specifically for this project. Per the user's explicit
statement when supplying these files: "Under OpenAI's applicable terms, I can
use these generated outputs in my own game project, including for commercial
purposes, subject to applicable law and third-party rights." These are **not**
LPC assets and carry no LPC-specific licence — any stylistic resemblance to
LPC pixel art is coincidental (an artifact of the generation prompt asking
for a pixel-art base-defence wall), not a derivative of any LPC source file.
Kept out of `sprites/lpc/` for the same reason `sprites/base/base-structure.png`
(also user-supplied, non-LPC art) is kept out of that directory — see
`sprites/base/NOTES.md` for the precedent.

## Processing applied

Each source file (`image-gen-N.png`, 1254×1254, RGBA with existing alpha
transparency — no black background was actually present, so no chroma-key
step was needed) was cropped to its own opaque-pixel bounding box using a
Playwright-driven canvas (alpha-channel scan, threshold 10/255) to remove the
surrounding transparent padding, with no resampling, recolouring, or redraw
of the pixel content itself:

| File | Level | Cropped size | Source |
|---|---|---|---|
| `wall-level-1.png` | 1 | 1055×617 | `image-gen-1(5).png` — rickety roped-log barricade |
| `wall-level-2.png` | 2 | 1133×649 | `image-gen-2(5).png` — reinforced wood wall with spikes |
| `wall-level-3.png` | 3 | 1131×733 | `image-gen-3(3).png` — stone rampart |
| `wall-level-4.png` | 4 | 1157×817 | `image-gen-4(2).png` — concrete/sandbag/razor-wire bunker wall |
| `wall-level-5.png` | 5 | 1079×813 | `image-gen-5.png` — armoured tech gate with warning lights |

Edge-fringe was checked (composited over a solid green background at full
resolution) and found clean on all five — no red/black halo pixels to clean
up, so no alpha-matte correction was applied.

## Rendering

`wall-render.ts`'s `renderWallImageLevel()` draws each file as a single
`drawImage` per wall segment (not tiled/repeated — each level is one wide
"panel" image stretched to fit that segment's screen-space footprint),
`imageSmoothingEnabled = false` for crisp nearest-neighbour pixel scaling,
anchored so the image's own bottom edge sits on the segment's real ground
line (same taller-than-hitbox/anchor-at-bottom convention the previous
procedural renderer and `renderBuilding` both already use). A vertical
(east/west) wall run reuses the same horizontal-facing image rotated 90°
around the segment's own centre — there is only one piece of art per level
(a horizontal gate/wall panel), not a separate vertical variant, so a
rotation is the only way to cover all four sides without inventing new art
the user did not supply.
